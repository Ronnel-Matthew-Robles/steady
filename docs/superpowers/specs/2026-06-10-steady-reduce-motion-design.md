# Steady: Reduce Motion & Calm the Web (Design)

Date: 2026-06-10
Status: Approved (spec authored by user; technical decisions confirmed)

## Purpose

A Manifest V3 Chrome extension that forcibly reduces motion and sensory overload
on every website, for users with vestibular disorders, migraines, ADHD, autism, and
motion sensitivity.

It improves on existing tools that either (a) overlay a screenshot to "freeze" the
page (breaks on scroll, makes the page non-interactive) or (b) only toggle the OS
`prefers-reduced-motion` flag (does nothing on the majority of sites that ignore it).
Steady injects reduced-motion CSS into every page so it works regardless, while
keeping the page fully interactive.

## Core principles (non-negotiable)

- Manifest V3. No backend, no network requests, no analytics, no ads. Fully offline.
- Storage: `chrome.storage.local` only (per-site exceptions + global toggle).
- Content script on `<all_urls>`, injected at `document_start`. Request the minimum
  permissions beyond that.

## Architecture

Vanilla JS, no build step (simpler to audit, maintain, and open-source).

| File | Role |
|------|------|
| `manifest.json` | MV3 manifest. Content script on `<all_urls>`, `run_at: document_start`, `all_frames: true`. Permissions: `storage`, `activeTab`. |

| `src/content.js` | Orchestrator: synchronously inject calm `<style>` at document_start; async-read settings and remove it if site is excepted/off; pause autoplaying media; freeze animated GIF/WebP; neutralize parallax; MutationObserver for late content; react to `storage.onChanged`. |

## Settings model

`chrome.storage.local`:

```json
{ "enabled": true, "allowed": { "example.com": true } }
```

- `enabled`: global toggle, default `true`.
- `allowed`: map of hostnames the user has chosen to *allow motion* on (per-site exception).
- Effective-calm for a page = `enabled && !allowed[hostname]`.
- Keyed by full `location.hostname`.
- Live updates via `chrome.storage.onChanged`; toggling applies/removes calming without
  a page reload.

## Feature mechanics

### 1. Force-reduce motion (CSS)

Injected ruleset forces animations/transitions to **complete instantly and hold end
state** (so reveal-on-scroll content still appears). Critically does NOT use
`animation: none` / `transition: none`.

```css
*, *::before, *::after {
  animation-duration: 0.001ms !important;
  animation-delay: 0ms !important;
  animation-iteration-count: 1 !important;
  transition-duration: 0.001ms !important;
  transition-delay: 0ms !important;
  scroll-behavior: auto !important;
}
html { scroll-behavior: auto !important; }
```

Plus conservative parallax neutralization (see #4).

### 2. Auto-pause autoplaying media

- Track `userInteracted` flag (first `pointerdown`/`keydown`/`touchstart`).
- On inject and on DOM mutation: pause `<video>`/`<audio>` that is autoplaying OR that
  begins playing before any user gesture.
- Never re-pause media the user explicitly started: a `play` listener only suppresses
  playback while `!userInteracted`.
- Re-checked via MutationObserver for late-loaded media.

### 3. Freeze animated GIF/WebP

- Candidates: `<img>` whose resolved URL is `.gif`/`.webp` (or `image/gif`,
  `image/webp` type), and `<picture>` sources.
- Draw first frame to an offscreen `<canvas>`, then set the **same** `<img>`'s `src`
  to the frozen data URL (preserves element identity, layout, attributes) instead of
  swapping in a `<canvas>` node.
- **Known limitation:** cross-origin images without CORS headers taint the canvas and
  cannot be read. Mitigation: attempt a `crossOrigin='anonymous'` reload first; if it
  still taints, leave the image untouched. Documented in README.
- Dynamic images handled via MutationObserver + per-image `load` listener.

### 4. Parallax neutralization (best-effort, conservative)

- CSS: `scroll-behavior: auto`.
- Override `background-attachment: fixed → scroll` (a very common pure-CSS parallax).
- Neutralize transforms on common parallax hooks (`[data-parallax]`, `.parallax`,
  `[data-rellax]`, etc.) where safe.
- **Limitation:** arbitrary JS transform-on-scroll parallax is only partially covered.
  We deliberately do NOT aggressively reset all inline transforms, to avoid breaking
  sticky headers and legitimate layouts. Documented as a limitation.

## Controls (popup)

- Global ON/OFF toggle (default ON).
- Per-site "Allow motion on this site" toggle, persisted in `chrome.storage.local`.
- Shows current site's hostname and effective status (Calm / Motion allowed / Off).
- Accessible: no animation/transition, full keyboard nav, visible focus, high contrast,
  min 14px text, proper ARIA on toggles.

## First-run

`onInstalled` opens `onboarding.html` once. ~2 sentences: it's ON, motion is calmed on
every site, and how to allow motion per-site.

## No-flash injection strategy

The content script (at `document_start`) synchronously inserts a `<style>` as the first
child of `documentElement` **before** reading storage (calm-by-default, effectively no
flash). It then async-reads settings and removes the `<style>` only if the site is
excepted or globally off. Failure mode is safe (calm). JS injection (not manifest `css`)
is used so the stylesheet can be cleanly toggled per-site.

## Testing

Manual matrix (per spec): heavy-parallax marketing site, autoplay-video site, GIF-heavy
page, scroll-reveal site (confirm content still appears). Confirm scroll/click/type work
throughout. Local `test/harness.html` reproduces each case offline.

## Out of scope (this pass)

Photosensitive-flash detection, color softening, ad/clutter hiding, sync, payments.

## Polish

Name "Steady"; Web Store title "Steady: Reduce Motion & Calm the Web". Calm, minimal
icon (no alarming reds; soft steady visual language). MIT LICENSE + clear README.

## Post-review amendments (2026-06-10)

A multi-agent adversarial review confirmed 16 findings; the implementation diverges
from the original design in these ways:

1. Dropped the unused `scripting` permission (least privilege).
2. Media/image mutations are gated until settings resolve (state machine:
   pending/calm/inactive), so excepted sites never get irreversibly frozen by the
   calm-by-default race. CSS stays eager since it is fully reversible.
3. Turning calming off (per-site or globally) now restores frozen images and resumes
   paused media live, not just on the next load. Originals are stashed in data
   attributes.
4. Per-site exceptions are keyed by the TOP page's hostname in every frame. The top
   frame registers its host with the service worker (chrome.storage.session); subframes
   query it and fall back to their own host.
5. The `userInteracted` one-shot latch was replaced with a rolling gesture window
   (1s after a trusted pointerdown/keydown/touchstart). Playback starting inside the
   window is marked user-played per element and never touched again; autoplay starting
   any time outside it is paused, even late in the page's life.
6. `.webp` is only rasterized after sniffing the VP8X animation flag, since most WebP
   on the web is static; unreadable bytes (no CORS) freeze anyway, favoring motion
   safety. GIFs freeze on sight.
7. `srcset` mutations (img and picture>source) are observed for lazy-loaded swaps.
8. Badge semantics: a small "off" badge appears only when Steady is NOT calming the
   page; the clean icon is the everyday working state.
9. Web Store title uses a colon, not a dash.

## Field-bug amendment (2026-06-11): the carousel strobe

Real-world testing on upwork.com found a critical flaw in the original CSS strategy.
Forcing `animation-duration`/`transition-duration` to 0.001ms makes
`transitionend`/`animationend` fire near-instantly, so any carousel or banner that
advances on those events (a very common pattern) cycles as fast as the event loop
allows: an infinite strobe, worse than the motion being suppressed.

The ruleset was rewritten: durations and delays are left untouched, and
`animation-timing-function`/`transition-timing-function` are forced to `step-start`
instead. Every animation and transition jumps straight to its end state visually but
still runs on the site's original clock, preserving event pacing. `animation-iteration-
count: 1` still applies. The original "complete instantly" CSS in the sections above is
superseded by this. Known trade-offs (documented in README): keyframe-internal timing
functions can override the rule per spec, and multi-keyframe animations step discretely
through their keyframes on the original schedule instead of finishing in one jump.

Regression coverage: unit tests assert the ruleset never touches durations/delays;
test/harness.html gained a transitionend-paced carousel; tools/e2e.mjs asserts the
carousel cadence is NOT accelerated under Steady and that the spinner is verifiably
still (sampled transforms) while its duration stays original.
